1.1从 .java 到运行：完整流水线

Java 的“跨平台”不是魔法，而是一层精心设计的中间层：先把源码编译成平台中立的字节码，再让每个平台上的 JVM 负责执行。

这条流水线带来两个直接后果。第一，编译一次之后，.class 文件可以在安装了 JVM 的 Windows、macOS、Linux 上运行。第二，Java 程序运行在 JVM 之上，因此启动比纯 native 程序多一层，但换来了内存安全、自动 GC 和统一的运行环境。

一句话记忆

JDK 包含 JRE，JRE 包含 JVM。开发需要 JDK；只运行别人做好的程序，理论上只需要 JRE（现代 JDK 也常直接用于运行）。

1.2JDK、JRE、JVM 到底是什么

名称包含什么你什么时候需要
JVM类加载器、执行引擎、运行时内存、GC运行任何 Java 字节码时；它通常由 JRE/JDK 提供
JREJVM + 核心类库（java.base 等）只运行、不开发（现代安装包中常被合并）
JDKJRE + javac、javadoc、jar、jshell 等工具写代码、编译、调试、打包——本课程需要

用终端验证一下。只要 java -version 和 javac -version 都能输出版本号，就说明 JDK 已经可用：

1.3第一个程序：逐行拆开看

新建文件 Hello.java，内容如下。文件名必须与 public class 的类名完全一致，包括大小写。

Hello.java
public class Hello {
    public static void main(String[] args) {
        String name = "未来的工程师";
        System.out.println("Hello, " + name + "!");
    }
}
Hello, 未来的工程师!
  1. public class Hello：定义一个公开类。Java 程序由类组织，public 表示这个类可以被其他包访问。
  2. public static void main(String[] args)：JVM 启动程序时寻找的入口签名。缺一个修饰符或参数类型不对，JVM 都不会把它当作入口。
  3. String name = "..."：在栈上声明一个引用变量，指向字符串对象。
  4. System.out.println(...)：System.out 是标准输出流，println 输出内容并换行。

在终端中进入文件所在目录，执行：

终端 · 编译与运行
javac -encoding UTF-8 Hello.java
java Hello

第一行会生成 Hello.class，第二行启动 JVM 并执行其中的字节码。注意：运行的是类名 Hello，不是文件名 Hello.class，也不要写成 java Hello.class。

三个高频错误

1. 文件名写成 hello.java：编译报 class Hello is public, should be declared in a file named Hello.java。
2. 运行时报 Could not find or load main class Hello：多半是当前目录不对，或类名拼错。
3. 中文乱码：编译时加 -encoding UTF-8，并确保终端/IDE 使用 UTF-8。

JDK 11 起还支持直接运行单文件源码：java Hello.java。它适合课堂演示，但真实项目仍使用 javac + 构建工具。

1.4包、目录与命名：工程习惯从第一天开始

小练习可以只有一个文件，但实际项目会用包（package）组织类。包名对应目录结构，通常使用公司域名的倒序：

目录结构
demo/
├─ src/
│  └─ com/example/app/
│     ├─ Main.java
│     └─ service/
│        └─ UserService.java
└─ out/

UserService.java 的第一行应声明 package com.example.app.service;。编译时用 -d out 指定输出目录，JVM 再通过 classpath 找到这些类。暂时理解“包名 = 目录路径”即可，第 15 章会用 Maven 自动管理。

元素规范示例
类 / 接口 / 枚举大驼峰 PascalCaseOrderService、UserRepository
方法 / 变量小驼峰 camelCasecalculateTotal、userName
常量全大写 + 下划线MAX_RETRY_COUNT
包全小写，点分层级com.example.order

命名不是审美问题。统一命名让代码可以被搜索、被工具分析，也让别人一眼看出“这是类还是变量”。从第一个作业开始就按规范写。

1.5输入、输出与注释

命令行程序最常用的输入是 Scanner。下面的程序读取姓名和年龄，再输出一句问候：

Greeting · Main.java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        System.out.println("请输入姓名：");
        String name = scanner.nextLine();

        System.out.println("请输入年龄：");
        int age = scanner.nextInt();

        System.out.printf("你好，%s！明年你 %d 岁。%n", name, age + 1);
        scanner.close();
    }
}
请输入姓名：
请输入年龄：
你好，小夏！明年你 21 岁。
OUTPUT

三种输出

print 不换行，println 换行，printf 用格式符（%s、%d、%.2f）排版。

COMMENTS

三种注释

// 单行，/* ... */ 多行，/** ... */ Javadoc。注释解释“为什么”，而不是复述代码。

一个容易忽略的细节：Scanner.nextInt() 只读取整数，不消耗行尾的换行符。如果后面紧接着调用 nextLine()，会读到一个空字符串。初学阶段建议统一用 nextLine() 读整行，再自行转换。

动手练习

把上面程序改成：读取两个整数，输出它们的和、差、积、商与余数。再故意输入 abc，观察 InputMismatchException——第 9 章会正式处理它。

1.6把错误分成两类，排错就成功了一半

COMPILE TIME

编译错误

代码不符合语法或类型规则，javac 直接拒绝生成 class。例如少分号、类型不匹配、类名与文件名不一致。程序根本没有运行。

RUNTIME

运行时异常

编译通过，但执行到某条语句时出错，例如除以零、数组越界、空指针。JVM 会打印异常类型、消息和调用栈。

读异常信息时，从第一行看类型，从调用栈找自己写的类，从行号定位语句。不要只看最后一行，也不要一看到红色就重写全部代码。

Exception in thread "main" java.lang.ArithmeticException: / by zero
    at Main.main(Main.java:4)

这条信息告诉你：Main.java 第 4 行发生了整数除以零。修复方式不是“加 try-catch 掩盖”，而是先确认业务上是否允许除数为零。

章节自测

下面哪一项包含 javac 编译器？

解析：JDK = JRE + 开发工具，javac、javadoc、jar 都在 JDK 中。JVM 负责执行字节码，不负责把源码编译成字节码。
章节自测

文件 Hello.java 中定义了 public class Hello。编译后正确的运行命令是？

解析：java 接收的是类名，不是文件名，也不能带 .class 后缀。JDK 11+ 虽然支持 java Hello.java 的源码启动模式，但它不是编译后再运行的常规方式。
章节自测

程序能编译，但运行时提示 Could not find or load main class Hello。最可能的原因是？

解析：能编译说明语法基本正确。JVM 在 classpath 中找不到指定的类，通常是因为没有在 .class 所在目录执行，或包名/类名与命令不一致。少分号会在编译阶段就失败。

2.1变量：给内存起一个名字

变量声明由三部分组成：类型 + 名字 +（可选）初始值。Java 是静态类型语言，变量一旦声明，类型就不能改变。

变量声明
int age = 20;              // 声明 + 初始化
double price = 19.9;       // 小数字面量默认 double
final int MAX_SCORE = 100; // final：只能赋值一次
var message = "hello";     // JDK 10+：由编译器推断为 String

age = 21;                  // 可以重新赋值
// MAX_SCORE = 120;        // 编译错误：final 变量不能再次赋值

var 不是“动态类型”。它只是让编译器根据等号右边的表达式推断类型，推断之后仍然是强类型。初学阶段建议显式写类型，等熟悉后再使用 var 减少冗长。

SCOPE

作用域

变量从声明处开始，到所在的 { } 块结束。内层块可以访问外层变量，外层不能访问内层变量。

DEFAULT

默认值

局部变量没有默认值，必须先赋值再使用；类的字段才有默认值（0、false、null）。

2.3字面量、转换与溢出

当不同类型一起运算时，Java 会按范围自动提升：byte → short → int → long → float → double，char 也会提升为 int。但“范围更大”不等于“精度更高”：int → float、long → double 都可能丢失低位。反过来从大范围转到小范围，必须显式强制转换，而且可能丢失信息。

Casting · Main.java
public class Main {
    public static void main(String[] args) {
        int i = 300;
        byte b = (byte) i;          // 只保留低 8 位
        System.out.println(b);      // 44

        double d = 3.99;
        int truncated = (int) d;    // 直接截断小数部分，不四舍五入
        System.out.println(truncated); // 3

        char ch = 'A';
        int code = ch;              // char 可以无损提升为 int
        System.out.println(code);   // 65

        System.out.println((char) (code + 1)); // B
    }
}
44
3
65
B

为什么 300 转成 byte 是 44？300 的二进制是 1 0010 1100，截取低 8 位得到 0010 1100，也就是 44。强制转换不会检查你是否“放得下”，它只负责截断。

溢出是静默的

int 的最大值是 2,147,483,647。再加 1 会变成 -2,147,483,648，而不是报错。涉及金额、计数等可能超界的场景，优先用 long 或 BigInteger，或者用 Math.addExact 让溢出显式抛出异常。阶乘增长极快，long 在 21! 就会溢出（第 4 章会看到）。

Overflow · Main.java
public class Main {
    public static void main(String[] args) {
        int max = Integer.MAX_VALUE;
        System.out.println(max + 1); // 溢出回绕

        try {
            System.out.println(Math.addExact(max, 1));
        } catch (ArithmeticException e) {
            System.out.println("ArithmeticException: " + e.getMessage());
        }
    }
}

原因在于 IEEE 754 二进制浮点数无法精确表示 0.1、0.2 这样的十进制小数，就像十进制无法精确表示 1/3。误差会在运算中累积。因此：

  1. 金额、利率、税费使用 BigDecimal，并且用字符串构造器：new BigDecimal("19.99")。用 new BigDecimal(19.99) 会把 double 的误差一起带进来。

  3. 除法必须指定精度和舍入模式：a.divide(b, 2, RoundingMode.HALF_UP)，否则除不尽时会抛 ArithmeticException。
  4. 科学计算、图形、统计可以继续用 double；它速度快，误差在可接受范围内。

4.4递归：自己调用自己

递归不是“高级技巧”，而是一种描述方式：把大问题变成同样结构的小问题。写递归必须同时满足三件事：

01

终止条件

最小规模时直接返回，不再调用自身。缺少它必定栈溢出。

02

规模缩小

每次调用都向终止条件靠近，例如 n - 1，且不能跳过或变大。

03

结果组合

假设子问题已解决，用它的结果组合出当前答案，如 n * fact(n-1)。

递归树与重复计算

朴素斐波那契递归会把同一个子问题算很多遍，时间复杂度约为 O(2ⁿ)：

Naive Fibonacci
static long fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);

改进方式有两种：用数组或 HashMap 做记忆化（自顶向下），或直接从小到大迭代（自底向上）。迭代版只保留前两个值，空间 O(1)：

FibonacciIterative · Main.java
public class Main {
    static long fib(int n) {
        if (n <= 1) return n;
        long prev = 0, curr = 1;
        for (int i = 2; i <= n; i++) {
            long next = prev + curr;
            prev = curr;
            curr = next;
        }
        return curr;
    }

    public static void main(String[] args) {

StackOverflowError

递归深度通常受线程栈大小限制（默认约数千到上万层，取决于 JVM 配置）。这不是“异常”，而是 Error。遇到它，先检查终止条件是否真的可达，再考虑改为迭代。

4.5方法设计：让调用者不必读实现

好的方法名应该像一句指令：calculateTotalPrice、isValidEmail、findActiveUsers。调用者看到名字就能知道它会做什么，而不需要点进去读十行。

  1. 参数少而明确。超过 3—4 个参数时，考虑封装成参数对象（如 OrderRequest），避免调用时把顺序记错。
  2. 避免布尔参数。sendEmail(user, true) 里的 true 含义不明；拆成 sendWelcomeEmail(user) 更清楚。
  3. 提前返回。先处理非法输入，再写主流程，减少嵌套层级。
  4. 不要修改调用者没预期的状态。方法名没有体现“修改”时，尽量保持无副作用；这会让测试和并发都更容易。
  5. 为边界写测试。空字符串、null、0、负数、最大值，往往才是 bug 的藏身处。

    public static void main(String[] args) {

结论

public class Main {
    static boolean isPalindrome(String s) {
        int left = 0;
        int right = s.length() - 1;
        while (left < right) {
            while (left < right && !Character.isLetterOrDigit(s.charAt(left))) left++;
            while (left < right && !Character.isLetterOrDigit(s.charAt(right))) right--;
            if (Character.toLowerCase(s.charAt(left)) != Character.toLowerCase(s.charAt(right))) {
                return false;
            }
            left++;
            right--;
        }
        return true;
    }

    public static void main(String[] args) {
        System.out.println(isPalindrome("A man, a plan, a canal: Panama")); // true
        System.out.println(isPalindrome("Java")); // false
    }
}

下面定义一个 Book 类。字段描述“它有什么”，方法描述“它能做什么”，构造器保证创建出来的对象一开始就处于合法状态。

BookDemo · Main.java
public class Main {
    static class Book {
        private final String title;
        private final String author;
        private int pages;

        Book(String title, String author, int pages) {
            if (title == null || title.isBlank()) {
                throw new IllegalArgumentException("书名不能为空");
            }
            if (pages <= 0) {
                throw new IllegalArgumentException("页数必须为正");
            }
            this.title = title;
            this.author = author;
            this.pages = pages;
        }

        void read(int count) {
            pages = Math.max(0, pages - count);
        }

        String describe() {
            return title + " / " + author + " / 剩余 " + pages + " 页";
        }
    }

    public static void main(String[] args) {
        Book book = new Book("Java 核心技术", "Horstmann", 900);
        System.out.println(book.describe());
        book.read(120);
        System.out.println(book.describe());
    }
}

  1. new Book(...)：在堆上分配对象内存，字段先取默认值，再执行构造器。
  2. this.title = title：this 指向当前对象，用来区分同名字段和参数。

构造器不是方法

6.2封装：把“能改什么”收进类里

封装不是“把所有字段都加 getter/setter”。它的核心是：对象自己维护状态的一致性，外部只能通过受控的接口改变它。

修饰符可见范围典型用途
private仅当前类字段、内部辅助方法
（默认）同一包包内协作，框架较少依赖
protected同包 + 子类为继承预留的扩展点
public所有地方对外 API、入口方法
封装示例
public class BankAccount {
    private long balance; // 外部不能直接改

    public void deposit(long amount) {
        if (amount <= 0) throw new IllegalArgumentException("存款必须为正");
        balance += amount;
    }

    public void withdraw(long amount) {
        if (amount <= 0) throw new IllegalArgumentException("取款必须为正");
        if (amount > balance) throw new IllegalStateException("余额不足");
        balance -= amount;
    }

    public long getBalance() {
        return balance;
    }
}

这里没有 setBalance。因为“直接设置余额”会绕过存款/取款的业务规则。只暴露必要的操作，比暴露所有字段更安全。

封装的三层价值

正确性：不让对象进入非法状态。可演进：内部实现可以换，调用者不受影响。可理解：公共方法就是类的使用说明书。

6.3实例成员与静态成员

实例字段属于每个对象，静态字段属于整个类，只有一份。每创建一个对象，实例字段就多一份；静态字段始终共享。

StaticDemo · Main.java
public class Main {
    static class User {
        static int createdCount = 0; // 类级别
        final String name;           // 对象级别

        User(String name) {
            this.name = name;

        }

    public static void main(String[] args) {

USE STATIC

适合静态

与对象状态无关的工具方法（Math.max）、全局常量、工厂方法、程序入口。

AVOID

谨慎使用

6.4对象在内存里长什么样

栈帧里保存局部变量。对对象来说，变量保存的是堆中对象的引用；对象本身（字段）在堆里。因此：

引用语义
Person a = new Person("Ada");
Person b = a;          // 复制引用，不复制对象
b.age = 21;            // 通过 b 修改的仍是同一个对象
System.out.println(a.age); // 21

a = null;              // a 不再引用对象，但 b 仍然引用
System.out.println(b.age); // 21，对象没有被回收

一个对象只有在从 GC Roots 不可达时才会被回收。把变量置为 null 只是删掉一条引用；如果还有其他引用，对象依然存活。第 14 章会深入 GC。

NullPointerException 的根源

引用为 null 时，调用任何实例方法或访问字段都会抛 NPE。防御式写法：if (obj != null)，或使用 Objects.requireNonNull 在入口处尽早失败。

6.5record：为数据载体减负

如果一个类的主要职责就是“携带一组不可变数据”，写构造器、getter、equals、hashCode、toString 会很啰嗦。JDK 16 起可以用 record：

RecordDemo · Main.java
public class Main {
    record Point(int x, int y) {
        Point {
            if (x < 0 || y < 0) {
                throw new IllegalArgumentException("坐标不能为负");
            }
        }

        int manhattan() {
            return x + y;
        }
    }

    public static void main(String[] args) {
        Point p = new Point(3, 4);
        System.out.println(p);            // Point[x=3, y=4]
        System.out.println(p.manhattan()); // 7
        System.out.println(p.equals(new Point(3, 4))); // true
    }
}

编译器自动生成：私有 final 字段、规范构造器、访问器 x() / y()、基于字段的 equals / hashCode / toString。record 适合 DTO、坐标、金额、事件等“值对象”，不适合需要可变状态或继承体系的实体。

record 不是“简化版 class”

它隐含 final，不能继承其他类，字段不可变。需要可变集合字段时要特别小心：record 只保证引用不变，不保证集合内容不变。

7.1extends：继承的语法与初始化顺序

子类继承父类的字段和方法，并可以添加自己的成员。创建子类对象时，一定先完成父类部分的初始化：

Inheritance · Main.java
public class Main {
    static class Animal {
        protected final String name;

        Animal(String name) {
            this.name = name;
            System.out.println("Animal 构造: " + name);
        }

        void speak() {
            System.out.println(name + " 发出声音");
        }
    }

    static class Dog extends Animal {
        Dog(String name) {
            super(name); // 必须第一行：调用父类构造器
            System.out.println("Dog 构造: " + name);
        }

        @Override
        void speak() {
            System.out.println(name + " 汪汪");
        }
    }

    public static void main(String[] args) {
        Dog dog = new Dog("旺财");
        dog.speak();
    }
}
Animal 构造: 旺财
Dog 构造: 旺财
旺财 汪汪

如果子类构造器没有显式写 super(...)，编译器会自动插入 super()。因此父类如果没有无参构造器，子类必须显式调用一个存在的父类构造器，否则编译失败。

is-a 关系

继承表达“Dog is-a Animal”。如果一句话说不通（例如“Car is-a Engine”），就不该用继承，而应该用组合：Car has-a Engine。

7.2重写与动态分派

重写（override）发生在父子类之间，方法名和参数列表必须相同。遵守三条规则：

  1. 访问权限不能更窄。父类方法是 public，子类不能改成 protected。
  2. 返回类型可以协变。父类返回 Animal，子类可以返回 Dog（Dog 是 Animal 的子类）。
  3. 不能抛出更宽的受检异常。父类抛 IOException，子类不能改抛 Exception。

调用 animal.speak() 时，编译器只检查 Animal 有没有 speak()；运行时 JVM 根据对象的实际类型选择方法。这就是动态分派，也是多态的实现机制。

Polymorphism · Main.java
public class Main {
    static class Animal {
        void speak() { System.out.println("..."); }
    }
    static class Dog extends Animal {
        @Override void speak() { System.out.println("汪汪"); }
    }
    static class Cat extends Animal {
        @Override void speak() { System.out.println("喵喵"); }
    }

    public static void main(String[] args) {
        Animal[] zoo = { new Dog(), new Cat(), new Dog() };
        for (Animal animal : zoo) {
            animal.speak(); // 同一行代码，三种实际行为
        }
    }
}

@Override 不是必需的，但强烈建议写。它让编译器帮你检查“是否真的重写了”，避免参数写错却悄悄变成重载。

字段没有多态

通过父类引用访问字段时，取的是编译时类型的字段。只有实例方法参与动态分派。不要依赖字段隐藏，这会让代码极难理解。

7.3Object 的三个基本契约

所有类都直接或间接继承 Object。其中 equals、hashCode、toString 最常被重写：

EqualsHashCode · Main.java
import java.util.Objects;

public class Main {
    static class User {
        final int id;
        final String name;

        User(int id, String name) {
            this.id = id;
            this.name = name;
        }

        @Override
        public boolean equals(Object o) {
            if (this == o) return true;
            if (!(o instanceof User other)) return false;
            return id == other.id && Objects.equals(name, other.name);
        }

        @Override
        public int hashCode() {
            return Objects.hash(id, name);
        }

        @Override
        public String toString() {
            return "User{id=" + id + ", name='" + name + "'}";
        }
    }

    public static void main(String[] args) {
        User a = new User(1, "Ada");
        User b = new User(1, "Ada");
        System.out.println(a == b);        // false
        System.out.println(a.equals(b));   // true
        System.out.println(a);             // User{id=1, name='Ada'}
    }
}

equals / hashCode 契约

如果 a.equals(b) 为 true，那么 a.hashCode() == b.hashCode() 必须成立。只重写 equals 不重写 hashCode，对象放进 HashMap / HashSet 时会“找不到自己”。

重写 equals 时依次判断：引用相同 → 类型兼容 → 关键字段相等。注意 instanceof 对 null 返回 false，因此可以同时处理空值。

7.4抽象类、final 与 sealed

抽象类表达“不完整的模板”：它可以包含已实现的方法，也可以声明没有方法体的抽象方法，强制子类实现。

AbstractShape · Main.java
public class Main {
    static abstract class Shape {
        abstract double area();

        void print() {
            System.out.printf("%s 面积 %.2f%n", getClass().getSimpleName(), area());
        }
    }

    static class Circle extends Shape {
        final double r;
        Circle(double r) { this.r = r; }
        @Override double area() { return Math.PI * r * r; }
    }

    static class Square extends Shape {
        final double side;
        Square(double side) { this.side = side; }
        @Override double area() { return side * side; }
    }

    public static void main(String[] args) {
        Shape[] shapes = { new Circle(2), new Square(3) };
        for (Shape shape : shapes) shape.print();
    }
}
ABSTRACT

抽象类

不能实例化；可以有字段、构造器和普通方法；适合“共享部分实现”的模板。

FINAL

final

修饰类：不能被继承；修饰方法：不能被重写；修饰变量：只能赋值一次。

SEALED

sealed

Sealed + switch 模式匹配（JDK 21+）
sealed interface Payment permits CardPayment, AlipayPayment {}
record CardPayment(String cardNo) implements Payment {}
record AlipayPayment(String account) implements Payment {}

class FeeCalculator {
    static double fee(Payment p) {
        return switch (p) {
            case CardPayment c -> 0.006;
            case AlipayPayment a -> 0.0;
        };
    }
}

7.5组合优于继承：一个真实的设计判断

继承是强耦合：子类依赖父类的实现细节，父类一改，子类可能悄悄坏掉。设计模式里有一句被反复引用的话：优先使用组合，而不是继承。

用组合实现“有引擎的车”
class Engine {
    void start() { System.out.println("引擎启动"); }
}

class Car {
    private final Engine engine; // has-a

    Car(Engine engine) {
        this.engine = engine;
    }

    void start() {
        engine.start();
        System.out.println("车辆准备出发");
    }
}

如果写成 class Car extends Engine，语义就变成“车是一种引擎”，既荒谬又让 Car 继承了不该拥有的行为。组合把关系表达为“使用”，还能在运行时替换实现（依赖注入的基础）。

里氏替换原则（LSP）

子类对象必须能够替换父类对象而不破坏程序。如果子类重写方法后抛出“不支持”、改变前置条件、或让原本成立的行为失效，就说明继承关系用错了。

经验法则：只有当子类确实是父类的一种，并且需要复用父类的多态接口时，才用继承。仅仅为了复用几行代码，用组合或工具方法更安全。

8.1接口：只约定能力，不绑定实现

接口中的抽象方法默认是 public abstract。一个类可以实现多个接口，从而获得多种“能力标签”。

InterfaceDemo · Main.java
public class Main {
    interface Flyable {
        void fly();

        default String describe() {
            return "我可以飞行";
        }

        static Flyable noop() {
            return () -> System.out.println("不会飞");
        }
    }

    interface Swimmable {
        void swim();
    }

    static class Duck implements Flyable, Swimmable {
        @Override public void fly() { System.out.println("鸭子扑腾翅膀"); }
        @Override public void swim() { System.out.println("鸭子划水"); }
    }

    public static void main(String[] args) {
        Duck duck = new Duck();
        duck.fly();
        duck.swim();
        System.out.println(duck.describe());
    }
}

default 方法让接口可以在不破坏已有实现的前提下新增行为，是 Java 8 引入的兼容性设计。static 方法属于接口本身，通过 Flyable.noop() 调用。

函数式接口

只有一个抽象方法的接口叫函数式接口，可以用 lambda 实现，例如 Runnable、Comparator、Predicate。加 @FunctionalInterface 让编译器帮你检查。

8.2接口还是抽象类？

维度接口抽象类
关系语义can-do / 能力契约is-a / 共享骨架
多继承一个类可实现多个接口只能继承一个类
状态不能有实例字段（常量除外）可以有实例字段
构造器没有有，供子类调用
方法实现抽象 / default / static / private抽象 / 具体方法都可以
典型用途解耦、插件、策略、API 契约模板方法、部分共享实现

选择时先问语义：如果只是“具备某能力”，用接口；如果存在“共同的状态和骨架流程”，用抽象类。很多框架会两者结合：接口定义契约，抽象类提供默认实现。

default 方法冲突
interface A { default void hello() { System.out.println("A"); } }
interface B { default void hello() { System.out.println("B"); } }

class C implements A, B {
    @Override
    public void hello() {
        A.super.hello(); // 必须显式选择
    }
}

如果两个接口提供相同的 default 方法，实现类必须重写并显式选择，否则编译错误。这避免了 C++ 式多继承的歧义。

8.3枚举：用类型替代魔法值

不要用 int status = 1 表示订单状态。枚举把合法取值限定在一个固定集合里，编译器会帮你检查。

OrderStatus · Main.java
public class Main {
    enum OrderStatus {
        CREATED("待支付", false),
        PAID("已支付", true),
        SHIPPED("已发货", true),
        CANCELLED("已取消", false);

        private final String label;
        private final boolean canShip;

        OrderStatus(String label, boolean canShip) {
            this.label = label;
            this.canShip = canShip;
        }

        boolean canShip() { return canShip; }
    }

    public static void main(String[] args) {
        OrderStatus status = OrderStatus.PAID;
        System.out.println(status.label);       // 已支付
        System.out.println(status.canShip());   // true
        System.out.println(status.ordinal());   // 1（不推荐依赖）

        for (OrderStatus s : OrderStatus.values()) {
            System.out.println(s + " -> " + s.label);
        }

        OrderStatus parsed = OrderStatus.valueOf("SHIPPED");
        System.out.println(parsed == OrderStatus.SHIPPED); // true
    }
}

每个枚举常量天然是单例，在 JVM 中只有一个实例，因此可以用 == 安全比较。枚举还适合实现状态机、策略表、单例模式。

不要依赖 ordinal

ordinal() 是声明顺序，插入一个新常量就会改变所有后续值。需要持久化或跨系统传输时，用自定义的稳定 code 字段。

8.4策略模式：把变化关进实现类

没有策略模式时，支付逻辑容易写成这样：

违反开闭原则的写法
public void pay(String type, BigDecimal amount) {
    if ("card".equals(type)) {
        // 信用卡逻辑
    } else if ("alipay".equals(type)) {
        // 支付宝逻辑
    } else if ("wechat".equals(type)) {
        // 微信逻辑
    }
    // 每新增一种方式，都要修改这个方法
}

把“支付”抽象成接口，每个实现类负责一种方式，订单服务只依赖接口：

策略 + 依赖注入
import java.math.BigDecimal;

interface Payment {
    void pay(BigDecimal amount);
}

class CardPayment implements Payment {
    public void pay(BigDecimal amount) { /* 银行网关 */ }
}

class OrderService {
    private final Payment payment;

    OrderService(Payment payment) { // 构造器注入
        this.payment = payment;
    }

    void checkout(BigDecimal amount) {
        payment.pay(amount);
    }
}

新增支付方式时，只需新增一个实现类，OrderService 完全不用改。这就是开闭原则：对扩展开放，对修改关闭。构造器注入让依赖显式化，也让测试可以传入假的 Payment。

8.5SOLID：五条设计原则的落地含义

原则一句话反例信号
S 单一职责一个类只有一个变化原因类名里出现“Manager”“Util”，方法跨越多个业务域
O 开闭新增功能靠扩展，而不是改旧代码每加一种类型就改一长串 if-else / switch
L 里氏替换子类必须能替换父类子类重写后抛“不支持”，或改变父类契约
I 接口隔离接口小而专，不强迫实现无关方法实现类里大量空方法或 throw new UnsupportedOperationException()
D 依赖倒置依赖抽象，不依赖具体实现业务类直接 new MySQLUserRepository()

原则不是教条。小脚本、一次性工具不需要全套架构；但在会持续迭代的项目里，它们能显著降低修改成本。

注解本身不改变程序逻辑，而是提供给编译器或框架读取的元数据。你已经见过 @Override，常见还有：

异常处理优雅地失败，而不是假装没发生

异常不是“错误代码”，而是程序在无法继续时传递信息的方式。好的异常处理让失败可定位、可恢复、可解释；坏的处理只是把问题藏起来，让它在更远的地方爆炸。

9.1异常体系的三个分支

异常层次（简化）
Throwable
├─ Error                    程序通常无法恢复
│  ├─ OutOfMemoryError
│  └─ StackOverflowError
└─ Exception
   ├─ RuntimeException      非受检，编译器不强制处理
   │  ├─ NullPointerException
   │  ├─ IllegalArgumentException
   │  └─ ArithmeticException
   └─ IOException          受检，必须处理或声明
      ├─ FileNotFoundException
      └─ ...
类别是否强制处理典型场景策略
Error否OOM、栈溢出、类加载失败通常不捕获，修复根因或让进程退出
受检异常是（catch 或 throws）文件、网络、数据库恢复、重试、包装后向上抛
运行时异常否空指针、参数非法、越界修 bug，或在边界做防御

“受检”意味着编译器会检查：一个可能抛出 IOException 的调用，要么放在 try-catch 中，要么在方法签名上写 throws IOException。这迫使调用者面对可能失败的事实。

不要捕获 Error

OutOfMemoryError 发生时 JVM 已处于不稳定状态，catch (Throwable t) 并不能让程序真正恢复，反而可能掩盖致命问题。

9.2try、catch、finally 与栈展开

TryCatch · Main.java
public class Main {
    public static void main(String[] args) {
        try {
            int result = 10 / 0;
            System.out.println("不会执行");
        } catch (ArithmeticException e) {
            System.out.println("捕获: " + e.getMessage());
        } finally {
            System.out.println("finally 一定执行");
        }

        try {
            Integer.parseInt("abc");
        } catch (NumberFormatException e) {
            System.out.println("格式错误: " + e.getMessage());
        }
    }
}
捕获: / by zero
finally 一定执行
格式错误: For input string: "abc"

finally 无论是否发生异常、是否 return，都会执行（除非 JVM 退出或进程被杀）。它适合释放资源，但现代 Java 更推荐 try-with-resources。

multi-catch
// 片段：假设 process / log / ServiceException 已在项目中定义
try {
    process(path);
} catch (IOException | SQLException e) {
    log.error("处理失败", e);
    throw new ServiceException("处理失败", e);
}

catch 顺序

子类异常必须放在父类异常前面。catch (Exception e) 放最前面会让后面的具体 catch 永远不可达，直接编译错误。

9.3try-with-resources：让关闭自动发生

文件、流、连接都必须关闭。手写 finally 容易漏、也容易在 close 时再抛异常。只要资源实现 AutoCloseable，就可以交给 try-with-resources：

Resources · Main.java
public class Main {
    static class Connection implements AutoCloseable {
        private final String name;
        Connection(String name) { this.name = name; }

        void query() {
            System.out.println(name + " 执行查询");
            throw new RuntimeException("查询失败");
        }

        @Override
        public void close() {
            System.out.println(name + " 已关闭");
        }
    }

    public static void main(String[] args) {
        try (Connection conn = new Connection("DB-1")) {
            conn.query();
        } catch (RuntimeException e) {
            System.out.println("捕获: " + e.getMessage());
        }
    }
}
DB-1 执行查询
DB-1 已关闭
捕获: 查询失败

即使 try 块抛异常，close 仍会被调用。多个资源按声明的逆序关闭；如果 close 也抛异常，它会被作为 suppressed 异常附加到主异常上，不会覆盖原始错误。

9.4自定义异常：把业务语义带上去

当调用者需要根据“余额不足”“库存不足”等业务原因做出不同反应时，自定义异常比一句字符串更清晰：

CustomException · Main.java
public class Main {
    static class InsufficientBalanceException extends RuntimeException {
        private final long balance;
        private final long required;

        InsufficientBalanceException(long balance, long required) {
            super("余额 " + balance + " 不足，需要 " + required);
            this.balance = balance;
            this.required = required;
        }

        long shortfall() { return required - balance; }
    }

    static void withdraw(long balance, long amount) {
        if (amount > balance) {
            throw new InsufficientBalanceException(balance, amount);
        }
        System.out.println("取款成功");
    }

    public static void main(String[] args) {
        try {
            withdraw(100, 150);
        } catch (InsufficientBalanceException e) {
            System.out.println(e.getMessage());
            System.out.println("还差: " + e.shortfall());
        }
    }
}
  1. 命名以 Exception 结尾。OrderNotFoundException 比 OrderError 更符合惯例。
  2. 提供有用的消息。包含关键标识（订单号、用户 ID）和期望值，但不要泄露密码、密钥等敏感信息。
  3. 保留原因。包装底层异常时传 cause：new ServiceException("下单失败", e)，否则异常链断裂，无法定位根因。
  4. 业务异常 vs 系统异常。业务异常通常可预期、可提示用户；系统异常（数据库宕机、网络超时）应记录日志并告警。

9.5五种坏味道：你可能正在这样写

BAD 01

空 catch

catch (Exception e) {} 把错误吞掉，程序继续运行在未知状态。至少记录日志，或明确注释为什么可以忽略。

BAD 02

catch Exception

捕获过宽会连带处理你不理解的异常，包括编程错误。尽量捕获具体的异常类型。

BAD 03

用异常做流程控制

用 try/catch 代替正常的 if 判断，会让性能与可读性都变差。异常应表达“异常情况”。

BAD 04

只 printStackTrace

生产环境应使用日志框架，带上上下文（请求 ID、用户、参数），而不是直接打印到标准错误。

BAD 05

丢失 cause

throw new RuntimeException("失败") 丢掉原始异常，堆栈只剩最外层。用带 cause 的构造器保留链路。

GOOD

边界处理

在系统边界（Controller、命令行入口）统一捕获、记录并转换为用户可读的错误；核心业务内部让异常向上传播。

10.4Map：键值映射与 HashMap 原理

MapDemo · Main.java
import java.util.HashMap;
import java.util.Map;

public class Main {
    public static void main(String[] args) {
        Map<String, Integer> stock = new HashMap<>();
        stock.put("apple", 10);
        stock.put("banana", 5);
        stock.put("apple", 8);            // 覆盖旧值
        System.out.println(stock.get("apple"));   // 8
        System.out.println(stock.getOrDefault("pear", 0)); // 0

        stock.merge("banana", 3, Integer::sum);   // 5 + 3
        stock.computeIfAbsent("cherry", k -> 20);

        for (Map.Entry<String, Integer> entry : stock.entrySet()) {
            System.out.println(entry.getKey() + " = " + entry.getValue());
        }
    }
}

HashMap 的核心步骤：计算 key 的哈希值 → 扰动 → 定位桶 → 若桶为空直接放入，否则用 equals 比较并处理冲突。JDK 8 起，当单个桶的链表过长且容量足够时会转为红黑树，最坏查找从 O(n) 改善为 O(log n)。

  1. 初始容量 16，负载因子 0.75。元素数量超过阈值（16 × 0.75 = 12）时扩容到 32，并重新分配元素。
  2. 哈希扰动。让高位也参与桶下标计算，减少规律性 key 的冲突。
  3. 冲突链。同一个桶里先比较哈希，再用 equals 判断是否同一个 key。
  4. 无序。HashMap 不保证遍历顺序；需要顺序用 LinkedHashMap，需要排序用 TreeMap。

key 的不可变性

作为 key 的对象，参与 hashCode / equals 的字段不应在放入后修改。否则哈希值变化，Map 再也找不到这个键。

10.5泛型：把类型检查提前到编译期

没有泛型时，集合什么都装，取出来必须强转，错误只能在运行时发现。泛型用类型参数把“装什么”写进类型：

GenericBox · Main.java
public class Main {
    static class Box<T> {
        private T value;

        void set(T value) { this.value = value; }
        T get() { return value; }
    }

    static <T extends Comparable<T>> T max(T a, T b) {
        return a.compareTo(b) >= 0 ? a : b;
    }

    public static void main(String[] args) {
        Box<String> box = new Box<>();
        box.set("hello");
        // box.set(123); // 编译错误，类型安全
        System.out.println(box.get().toUpperCase());

        System.out.println(max(3, 7));
        System.out.println(max("apple", "banana"));
    }
}

通配符与 PECS

Wildcards
import java.util.List;

public class Main {
    // Producer Extends：只读取，用 ? extends
    static double sum(List<? extends Number> nums) {
        double total = 0;
        for (Number n : nums) total += n.doubleValue();
        return total;
    }

    // Consumer Super：只写入，用 ? super
    static void addInts(List<? super Integer> list) {
        list.add(1);
        list.add(2);
    }

    public static void main(String[] args) {
        List<Integer> ints = List.of(1, 2, 3);
        List<Double> doubles = List.of(1.5, 2.5);
        System.out.println(sum(ints) + sum(doubles)); // 10.0
    }
}

PECS：Producer Extends, Consumer Super。生产者（你从里面读）用 ? extends T，消费者（你往里面写）用 ? super T。如果既读又写，就不要用通配符。

import java.util.Comparator;
import java.util.List;

public class Main {
    public static void main(String[] args) {

11.3Stream：先描述，再执行

Stream 不是集合，不存储数据，也不修改原集合。它是一条惰性流水线：中间操作只是记录步骤，遇到终端操作才真正执行。

StreamPipeline · Main.java
import java.util.List;

public class Main {
    public static void main(String[] args) {
        List<String> names = List.of("Ada", "Bob", "Cathy", "Alice", "David", "Eve");

        List<String> result = names.stream()
                .filter(name -> name.length() > 3)
                .map(String::toUpperCase)
                .sorted()
                .toList();   // JDK 16+

        System.out.println(result); // [ALICE, CATHY, DAVID]
    }
}
INTERMEDIATE

中间操作

filter、map、flatMap、sorted、distinct、limit、skip、peek。返回新的 Stream。

TERMINAL

终端操作

collect、toList、forEach、count、reduce、anyMatch、findFirst。触发执行并结束流。

流只能消费一次

一个 Stream 执行终端操作后就关闭，再次使用会抛 IllegalStateException。需要复用数据时，从原集合重新 stream()，不要把 Stream 存成字段到处传。

import java.util.*;
import java.util.stream.Collectors;

public class Main {
    record Order(String customer, int amount) {}

    public static void main(String[] args) {
        List<Order> orders = List.of(
            new Order("Ada", 120),
            new Order("Bob", 80),
            new Order("Ada", 200),
            new Order("Cathy", 50)
        );

        // 过滤 + 映射 + 排序
        List<String> big = orders.stream()
                .filter(o -> o.amount() >= 100)
                .sorted(Comparator.comparingInt(Order::amount).reversed())
                .map(Order::customer)
                .toList();
        System.out.println(big); // [Ada, Ada]

        // 聚合
        int total = orders.stream().mapToInt(Order::amount).sum();
        double avg = orders.stream().mapToInt(Order::amount).average().orElse(0);
        System.out.println(total + " / " + avg);

        // 分组
        Map<String, List<Order>> byCustomer = orders.stream()
                .collect(Collectors.groupingBy(Order::customer));
        System.out.println(byCustomer.keySet());

        // 拼接
        String names = orders.stream()
                .map(Order::customer)
                .distinct()
                .collect(Collectors.joining(", ", "[", "]"));
        System.out.println(names); // [Ada, Bob, Cathy]
    }
}

适合

不适合

12.5实战：读取 CSV 并统计

假设有一份成绩文件 scores.csv：

Ada,92

目标：跳过表头，计算平均分，并找出最高分。这个例子把文件 IO、字符串切分、异常处理与集合串在一起：

CsvStats.java
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.*;
import java.util.*;

public class CsvStats {
    record Row(String name, int score) {}

    public static void main(String[] args) throws IOException {
        Path path = Path.of("scores.csv");
        List<Row> rows = new ArrayList<>();

        try (var lines = Files.lines(path, StandardCharsets.UTF_8)) {
            lines.skip(1)
                 .filter(line -> !line.isBlank())
                 .forEach(line -> {
                     String[] parts = line.split(",");
                     rows.add(new Row(parts[0].trim(), Integer.parseInt(parts[1].trim())));
                 });
        }

        double avg = rows.stream().mapToInt(Row::score).average().orElse(0);
        Row top = rows.stream().max(Comparator.comparingInt(Row::score)).orElseThrow();

        System.out.printf("平均分 %.1f，最高分 %s (%d)%n", avg, top.name(), top.score());
    }
}

13.1线程：程序里的第二条时间线

进程拥有独立内存空间；线程共享进程的堆和方法区，但各自有栈和程序计数器。并发是“交替推进”，并行是“真正同时执行”，前者是后者的基础。

ThreadDemo · Main.java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        Thread worker = new Thread(() -> {
            for (int i = 0; i < 3; i++) {
                System.out.println("worker: " + i);
                try {
                    Thread.sleep(100);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                    return;
                }
            }
        });

        worker.start();          // 启动新线程
        worker.join();           // main 等待 worker 结束
        System.out.println("main 结束");
    }
}

start() 与 run()

start() 才创建新线程并让 JVM 调度 run()；直接调用 run() 只是普通方法调用，仍在当前线程执行。这是经典面试题。

线程状态包括 NEW、RUNNABLE、BLOCKED、WAITING、TIMED_WAITING、TERMINATED。sleep 不释放锁，wait 会释放锁——这个差异在后面的锁章节还会遇到。

13.2竞态条件：一次更新如何消失

counter++ 看起来是一行，实际包含“读取 → 加一 → 写回”三个步骤。两个线程可能同时读到旧值，各自加一后写回，后写的覆盖先写的。

ATOMICITY

原子性

一个操作不可被中断。i++ 不是原子操作；synchronized 块内的复合操作可以成为原子操作。

VISIBILITY

可见性

一个线程的修改，另一个线程是否立刻能看到。CPU 缓存与编译器优化都可能导致“看不到”。

ORDERING

有序性

编译器和 CPU 可能重排指令。Java 内存模型（JMM）通过 happens-before 规则定义哪些重排是允许的。

JMM 不是“内存的物理结构”，而是一套并发行为的规则。它保证：程序顺序、监视器锁、volatile、线程启动/终止等关系形成 happens-before，从而让某些写入对后续读取可见。

13.3同步：把临界区保护起来

最直接的方案是用 synchronized 锁住共享状态。同一个锁同一时刻只能被一个线程持有：

public class Main {
    static class Counter {
        private int value;

        synchronized void increment() {
            value++;
        }

        synchronized int get() {
            return value;
        }
    }

    public static void main(String[] args) throws InterruptedException {
        Counter counter = new Counter();
        Runnable task = () -> {
            for (int i = 0; i < 1000; i++) counter.increment();
        };

        Thread a = new Thread(task);
        Thread b = new Thread(task);
        a.start();
        b.start();
        a.join();
        b.join();

        System.out.println(counter.get()); // 2000
    }
}

13.4线程池与异步任务

不要为每个任务 new Thread()。线程创建和销毁有成本，数量也无法控制。用线程池复用线程，并限制并发度：

ExecutorDemo · Main.java
import java.util.concurrent.*;

public class Main {
    public static void main(String[] args) throws Exception {
        ExecutorService pool = Executors.newFixedThreadPool(2);

        Future<Integer> future = pool.submit(() -> {
            Thread.sleep(300);
            return 21 * 2;
        });

        System.out.println("任务已提交");
        System.out.println("结果: " + future.get()); // 阻塞等待

        pool.shutdown();
        pool.awaitTermination(2, TimeUnit.SECONDS);
    }
}

CompletableFuture<String> userFuture =
        CompletableFuture.supplyAsync(() -> fetchUser(id), pool);

13.5虚拟线程：为高并发 IO 而生

JDK 21 正式引入虚拟线程。它由 JVM 调度，而不是一一绑定操作系统线程；遇到阻塞 IO 时会自动让出载体线程，因此可以用“一个请求一个线程”的简单写法支撑大量并发连接。

try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 10_000; i++) {
        executor.submit(() -> {
            Thread.sleep(1000); // 阻塞时让出载体线程
            return null;
        });
    }
}
适合

Web 请求、数据库访问、远程调用等大部分时间在等待的任务。虚拟线程能显著提高吞吐量。

虚拟线程不是“替代所有线程池”。它更适合请求级并发；计算密集型任务仍应使用固定大小的平台线程池。

13.6并发集合与生产者—消费者

HashMap、ArrayList 都不是线程安全的。并发场景优先使用 java.util.concurrent 包中的集合：

并发集合特点
ConcurrentHashMap高并发读写，CAS + 桶级 synchronized（Java 7 及以前才是分段锁），不允许 null key/value

import java.util.concurrent.*;

public class Main {
    public static void main(String[] args) {
        BlockingQueue<String> queue = new ArrayBlockingQueue<>(10);

        Thread producer = new Thread(() -> {
            try {
                queue.put("task-1"); // 队列满时阻塞
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });

        Thread consumer = new Thread(() -> {
            try {
                String task = queue.take(); // 队列空时阻塞
                System.out.println("处理 " + task);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        });

        producer.start();
        consumer.start();
    }
}

上面的两个线程分别扮演生产者和消费者。put 在队列满时阻塞，take 在队列空时阻塞，因此不需要手写 wait/notify。停止消费者时，可以放入一个“毒丸”消息，或使用中断。

并发编程的第一原则

能不共享就不共享。把状态限制在单个线程内（线程封闭），或使用不可变对象，比任何锁都更可靠。只有在确实需要共享可变状态时，才引入同步。

虚拟机栈栈帧：局部变量、操作数栈、返回地址否StackOverflowError
本地方法栈native 方法调用否栈溢出
堆对象实例、数组是OutOfMemoryError: Java heap space
方法区 / 元空间类元数据；静态字段值随 Class 对象在堆中（字符串常量池自 JDK 7 起也在堆）是Metaspace OOM

“栈”和“堆”不是抽象比喻：栈帧随方法调用压入/弹出，生命周期确定；堆对象由 GC 管理，生命周期不确定。局部变量在栈上，对象内容在堆上，引用把两者连起来。

逃逸分析

JIT 可能发现某个对象只在方法内使用、不会逃逸，于是把它分配在栈上或直接标量替换。这属于运行时优化，不改变 Java 语义。

14.2类加载与初始化顺序

类加载分为加载、验证、准备、解析、初始化。准备阶段给静态变量分配内存并赋零值；初始化阶段才执行静态赋值和静态代码块。

        static { System.out.println("Child 静态块"); }

Child 静态块
Parent 构造器
Child 构造器

静态初始化发生在类首次主动使用时，且只执行一次。注意输出顺序：main 先打印“准备创建 Child”，直到 new Child() 才触发类初始化，因此父类静态块先于子类静态块；实例化时，父类构造器先于子类构造器执行。

双亲委派

类加载器收到加载请求时，先委托父加载器尝试，父加载器无法完成才自己加载。这样保证核心类（如 java.lang.String）不会被自定义类冒充，提升安全性。常见加载器：Bootstrap → Platform → Application → 自定义。

14.3垃圾回收：从 GC Roots 出发

JVM 不靠引用计数，而靠可达性分析：从 GC Roots（栈上引用、静态字段、JNI 引用等）出发，能走到的对象存活，走不到的可回收。因此循环引用不会造成 Java 内存泄漏。

G1

G1 GC

JDK 9+ 默认。把堆划分为 Region，按收益优先回收，追求可预测的停顿时间。适合大多数服务端应用。

ZGC

ZGC

低延迟收集器，停顿通常在毫秒级，适合大堆、对延迟敏感的系统。吞吐量可能略低于 G1。

常用 GC 参数
-Xms2g -Xmx2g                  # 固定堆大小，避免动态扩缩
-XX:+UseG1GC                   # 使用 G1（通常默认）
-XX:MaxGCPauseMillis=200       # G1 目标停顿时间
-XX:+UseZGC                    # 使用 ZGC
-Xlog:gc*:file=gc.log:time     # 输出 GC 日志

调优的第一步不是改参数，而是测量：到底是内存泄漏、GC 停顿、锁竞争，还是下游 IO 慢？没有指标就调 JVM，等于蒙眼开车。

14.5Java 也会内存泄漏

虽然 GC 会自动回收不可达对象，但如果对象被“不该存在的引用”长期持有，它就一直可达，表现为内存持续上涨。常见来源：

  1. 静态集合只增不减。例如 static Map<String, User> CACHE 没有淘汰策略，等同于无限缓存。
  2. ThreadLocal 未 remove。线程池中的线程长期存活，ThreadLocal 的值会跟着线程一直存在。
  3. 监听器 / 回调未注销。被注册的对象持有外部引用，生命周期被意外延长。
  4. 资源未关闭。连接、流、文件句柄泄漏，最终拖垮系统（可能不是堆 OOM）。
  5. equals/hashCode 写错。对象放进 HashSet 后无法被删除，集合越来越大。

定位方法：用 jmap 导出堆快照，在 MAT / VisualVM 中查看 dominator tree，找到“谁在持有这些对象”。不要凭直觉猜。

Soft / Weak / Phantom Reference

缓存可以用 SoftReference（内存不足时回收）或 WeakHashMap（key 只被弱引用时回收），但它们不是万能缓存。生产缓存应使用 Caffeine 等带容量与过期策略的库。

14.6JIT 与性能：别猜，测量

JVM 先用解释器快速启动，再对热点代码进行 JIT 编译。C1 编译快、优化保守；C2 编译慢、优化激进（内联、逃逸分析、循环优化）。这使得 Java 程序常有“预热后变快”的现象。

观察 JIT 编译
-XX:+PrintCompilation
-XX:+UnlockDiagnosticVMOptions -XX:+PrintInlining
# 仅用于观察阈值：关闭分层编译后 CompileThreshold 才生效
-XX:-TieredCompilation -XX:CompileThreshold=10000
DON'T

微优化陷阱

用 System.currentTimeMillis 包一层循环测性能，结果会被 JIT、GC、预热和死代码消除彻底带偏。

DO

JMH

性能优化的顺序：先保证正确，再找瓶颈，再改算法/数据结构，最后才考虑 JVM 参数与微优化。大多数“性能问题”其实是 N+1 查询、无界缓存或错误的集合选择。

15.1JUnit 5：把预期写成可执行的代码

单元测试验证一个小的行为单元，运行快、彼此独立、失败时能直接指出问题。JUnit 5 是目前 Java 生态的标准选择。下面同时给出被测类和测试：

CalculatorTest.java
import org.junit.jupiter.api.*;
import static org.junit.jupiter.api.Assertions.*;

class Calculator {
    int add(int a, int b) {
        return Math.addExact(a, b); // 溢出时抛出 ArithmeticException
    }

    int divide(int a, int b) {
        return a / b; // 除数为 0 时抛出 ArithmeticException
    }
}

class CalculatorTest {

    private Calculator calculator;

    @BeforeEach
    void setUp() {
        calculator = new Calculator();
    }

    @Test
    @DisplayName("两个正数相加")
    void add_positiveNumbers() {
        int result = calculator.add(2, 3);
        assertEquals(5, result);
    }

    @Test
    void divide_byZero_shouldThrow() {
        ArithmeticException ex = assertThrows(
            ArithmeticException.class,
            () -> calculator.divide(10, 0)
        );
        assertEquals("/ by zero", ex.getMessage());
    }

    @Test
    void add_overflow_shouldThrow() {
        assertThrows(ArithmeticException.class,
            () -> calculator.add(Integer.MAX_VALUE, 1));
    }
}
注解 / 断言作用
@Test标记测试方法
@BeforeEach / @AfterEach每个测试前后执行，准备/清理环境
@BeforeAll / @AfterAll整个测试类前后执行一次；默认必须是 static 方法（使用 @TestInstance(PER_CLASS) 时可非静态）
@DisplayName给测试一个可读名字
assertEquals / assertTrue验证值或条件
assertThrows验证抛出预期异常
assertAll组合多个断言，全部执行后统一报告

测试结构：AAA

Arrange 准备数据与对象，Act 执行被测动作，Assert 验证结果。一个测试只验证一个行为，失败时才能一眼看出原因。

15.2从测试出发：TDD 与测试设计

TDD（测试驱动开发）的节奏是：先写一个失败的测试（红），再写最小实现让它通过（绿），最后重构。它强迫你先想清楚“什么叫做对了”。

  1. 红：为新行为写测试，运行，确认它因正确的原因失败。
  2. 绿：写最简单的实现让测试通过，不提前设计过度。
  3. 重构：在测试保护下消除重复、改善命名与结构。

测试用例要覆盖三类情况：正常路径、边界值（0、空、最大/最小、临界点）、错误路径（非法参数、null、异常）。只测“2 + 3 = 5”远远不够。

UNIT

单元测试

只测一个类/方法，依赖用 mock 或 fake 替代。快速、稳定，数量应最多。

INTEGRATION

集成测试

验证数据库、HTTP、消息队列等真实协作。较慢，数量适中。

测试金字塔：大量单元测试 + 少量集成测试 + 极少量端到端测试。反过来的“冰淇淋筒”会导致测试慢、脆弱、维护成本高。

15.5调试：比打印更高效的定位方式

IDE 调试器能暂停程序、查看变量、单步执行、计算表达式。常用能力：

  1. 行断点：在可疑语句处暂停，检查调用栈与局部变量。
  2. 条件断点：只有 userId == 42 时才停，避免在循环里反复中断。
  3. 异常断点：在异常抛出点暂停，直接看到“第一现场”，而不是只看到上层 catch。
  4. Evaluate Expression：在暂停时执行表达式，验证你的假设。
  5. 远程调试：通过 -agentlib:jdwp=... 连接测试环境（仅限受控网络）。

调试的核心不是“会按按钮”，而是提出假设 → 设计实验 → 验证或推翻。如果一个问题无法稳定复现，先补日志与指标，把不确定性变成可观察的数据。

        Book(String isbn, String title) {
            if (isbn == null || isbn.isBlank()) throw new IllegalArgumentException("ISBN 不能为空");
            if (title == null || title.isBlank()) throw new IllegalArgumentException("书名不能为空");
            this.isbn = isbn;
            this.title = title;
        }

        @Override
        public String toString() {
            return title + "(" + isbn + ")" + (available ? " [可借]" : " [已借出]");
        }
    }

    static class Member {
        final String id;
        final String name;
        final List<String> borrowedIsbns = new ArrayList<>();

        Member(String id, String name) {
            this.id = id;
            this.name = name;
        }
    }

    record Loan(String isbn, String memberId, LocalDate dueDate) {}

    static class LibraryService {
        private final Map<String, Book> books = new LinkedHashMap<>();
        private final Map<String, Member> members = new LinkedHashMap<>();
        private final List<Loan> loans = new ArrayList<>();

        void addBook(String isbn, String title) {
            if (books.containsKey(isbn)) throw new IllegalStateException("ISBN 已存在: " + isbn);
            books.put(isbn, new Book(isbn, title));
        }

        void register(String id, String name) {
            if (members.containsKey(id)) throw new IllegalStateException("读者 ID 已存在: " + id);
            members.put(id, new Member(id, name));
        }

        Loan borrow(String memberId, String isbn) {
            return borrow(memberId, isbn, LocalDate.now());
        }

        Loan borrow(String memberId, String isbn, LocalDate today) {
            Member member = requireMember(memberId);
            Book book = requireBook(isbn);
            if (member.borrowedIsbns.contains(isbn)) throw new IllegalStateException("不能重复借同一本书");
            if (!book.available) throw new IllegalStateException("图书已借出: " + book.title);
            book.available = false;
            member.borrowedIsbns.add(isbn);
            Loan loan = new Loan(isbn, memberId, today.plusDays(14));
            loans.add(loan);
            return loan;
        }

        void returnBook(String memberId, String isbn) {
            Member member = requireMember(memberId);
            Book book = requireBook(isbn);
            if (!member.borrowedIsbns.remove(isbn)) {
                throw new IllegalStateException("该读者没有借这本书");
            }
            book.available = true;
            loans.removeIf(loan -> loan.isbn().equals(isbn) && loan.memberId().equals(memberId));
        }

        List<Book> search(String keyword) {
            String k = keyword.toLowerCase(Locale.ROOT);
            return books.values().stream()
                    .filter(b -> b.title.toLowerCase(Locale.ROOT).contains(k))
                    .toList();
        }

        private Member requireMember(String id) {
            Member m = members.get(id);
            if (m == null) throw new IllegalArgumentException("读者不存在: " + id);
            return m;
        }

        private Book requireBook(String isbn) {
            Book b = books.get(isbn);
            if (b == null) throw new IllegalArgumentException("图书不存在: " + isbn);
            return b;
        }
    }

    public static void main(String[] args) {
        LibraryService library = new LibraryService();
        library.addBook("978-7-111-1", "Java 核心技术");
        library.addBook("978-7-111-2", "Effective Java");
        library.register("u1", "Ada");

        System.out.println(library.search("java"));
        // 传入固定日期，让示例输出可复现；真实调用可用 LocalDate.now()
        Loan loan = library.borrow("u1", "978-7-111-1", LocalDate.of(2026, 10, 21));
        System.out.println("借阅成功，应还日期: " + loan.dueDate());
        System.out.println(library.search("java"));

        library.returnBook("u1", "978-7-111-1");
        System.out.println(library.search("java"));

        try {
            library.borrow("u1", "978-7-111-2");
            library.borrow("u1", "978-7-111-2");
        } catch (IllegalStateException e) {
            System.out.println("业务拒绝: " + e.getMessage());
        }
    }

16.4给业务规则写测试

项目里最值得测试的不是 getter，而是“借书规则”。每个验收标准至少对应一个测试。下面的测试与 Main 放在同一文件（或同一包）中，因此可以直接访问单文件版里的嵌套类：

LibraryServiceTest.java
import org.junit.jupiter.api.*;
import static org.junit.jupiter.api.Assertions.*;

class LibraryServiceTest {
    private Main.LibraryService library;

    @BeforeEach
    void setUp() {
        library = new Main.LibraryService();
        library.addBook("isbn-1", "Clean Code");
        library.register("u1", "Ada");
        library.register("u2", "Bob");
    }

    @Test
    void borrow_marksBookUnavailable() {
        library.borrow("u1", "isbn-1");
        assertFalse(library.search("clean").get(0).available);
    }

    @Test
    void borrow_sameBookTwice_shouldThrow() {
        library.borrow("u1", "isbn-1");
        assertThrows(IllegalStateException.class,
            () -> library.borrow("u1", "isbn-1"));
    }

    @Test
    void return_byNonBorrower_shouldThrow() {
        library.borrow("u1", "isbn-1");
        assertThrows(IllegalStateException.class,
            () -> library.returnBook("u2", "isbn-1"));
    }

    @Test
    void search_isCaseInsensitive() {
        assertEquals(1, library.search("CLEAN").size());
    }
}

注意测试之间互不影响：每个测试在 @BeforeEach 中重建数据。共享可变状态会让测试顺序影响结果，这是测试中最常见的“灵异事件”。

扩展时最重要的检查：Service 的代码是否几乎不用改？如果换存储实现要重写业务逻辑，说明分层没有做好。可以用接口 BookRepository 把 Map 实现隔离起来：

面向接口的仓储
interface BookRepository {
    Optional<Book> findByIsbn(String isbn);
    List<Book> searchByTitle(String keyword);
    void save(Book book);
}

class InMemoryBookRepository implements BookRepository { /* Map 实现 */ }
class JdbcBookRepository implements BookRepository { /* SQL 实现 */ }

Service 只依赖 BookRepository，构造时注入具体实现。测试时注入内存版，生产时注入 JDBC 版——这就是依赖倒置的实际收益。

在分层架构中，LibraryService 最不应该直接依赖？

解析：Service 应依赖仓储接口，而不是具体数据库实现。这样替换存储、编写测试都不需要改业务代码，符合依赖倒置原则。

@RestController
@RequestMapping("/api/books")
public class BookController {
    private final BookService service;

    public BookController(BookService service) {
        this.service = service;
    }

    @GetMapping("/{isbn}")
    public BookResponse get(@PathVariable String isbn) {
        return service.findByIsbn(isbn);
    }

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public BookResponse create(@Valid @RequestBody CreateBookRequest request) {
        return service.create(request);
    }
}

注意：Controller 只负责 HTTP 协议与参数，业务规则仍在 Service。不要把它们混成一个“万能类”。
